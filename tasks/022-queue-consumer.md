# 022. Реализовать Worker consumer массовой операции

**Этап:** 5. Выполнение, повтор и восстановление

## Цель

Безопасно обработать каждую задачу независимо с соблюдением rate limit и конфликт-контроля.

## Контекст продукта

Непосредственно перед записью задача перечитывается; изменившаяся задача получает `Конфликт`.

## Объём

- Обрабатывать задачи операции по устойчивой очереди.
- Сверять контрольную версию и повторно проверять необходимые права.
- Применять изменения от имени текущего пользователя через adapter.
- Сохранять результат, предыдущие значения и версию после изменения по каждой задаче.
- Классифицировать временные и постоянные ошибки и соблюдать API rate limits.

## Вне объёма

UI прогресса, отчёты и ручной повторный прогон.

## Требования

- Ошибка одной задачи не останавливает остальные.
- Повторная доставка сообщения не изменяет уже окончательно обработанную задачу повторно.

## Критерии приёмки

- Конфликтная задача не перезаписывается и получает статус `Конфликт`.
- Каждый успешный и неуспешный результат сохраняется отдельно.
- Временный rate limit приводит к контролируемому retry без потери задач.
- Повторная доставка подтверждена тестом идемпотентности.
