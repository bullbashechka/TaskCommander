# 009. Реализовать запуск и идентификацию через Битрикс24

**Этап:** 3. Идентификация, права и управление доступом

## Цель

Определять текущего пользователя из контекста локального приложения Битрикс24 без отдельной учётной записи.

## Контекст продукта

Task Commander открывается внутри корпоративного портала и при каждом входе проверяет активность сотрудника.

## Объём

- Принять и серверно проверить OAuth-контекст запуска.
- Получить текущего пользователя, его активность и административный статус.
- Создать защищённую серверную сессию с ограниченным сроком жизни.
- Реализовать отказ для деактивированного или уволенного сотрудника.

## Вне объёма

Собственная регистрация, пароли, Supabase Auth и webhook-авторизация.

## Требования

- OAuth-токены не сохраняются в браузерном хранилище и не выводятся в логи.
- Проверка активности и прав выполняется при каждом новом входе.

## Критерии приёмки

- Активный пользователь входит без отдельной формы авторизации.
- Поддельный, просроченный или неполный контекст запуска отклоняется.
- Деактивированный пользователь получает отказ до загрузки продуктовых данных.
- Администратор Битрикс24 корректно определяется для последующего полного доступа.

## Зависимости

004, 006.

## Примечания по реализации

Локально используется mock-контекст; production OAuth подключается в задаче 035.
