# 007. Реализовать неизменяемый журнал событий аудита

**Этап:** 2. Данные и серверные инварианты

## Цель

Гарантировать полную, неизменяемую фиксацию значимых действий первой версии.

## Контекст продукта

PRD требует аудит операций, доступа, экспорта, автоматических отзывов и системных ошибок со сроком хранения два года.

## Объём

- Реализовать append-only сервис записи `AuditEvent`.
- Зафиксировать типы событий и обязательные поля.
- Запретить прикладное обновление и ручное удаление записей.
- Встроить безопасную очистку чувствительных технических данных.

## Вне объёма

Экран просмотра аудита и автоматическое удаление по сроку хранения.

## Требования

- Каждая запись содержит время, инициатора, тип, объект, результат и correlation ID.
- Токены и защищённые предыдущие значения не попадают в аудит.

## Критерии приёмки

- Все типы событий раздела 4.17 PRD представлены в контракте.
- API приложения не предоставляет изменение или удаление события.
- Попытка записать событие без обязательных полей отклоняется.
- Тесты подтверждают редактирование чувствительных значений до записи.
