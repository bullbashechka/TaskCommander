# 006. Реализовать серверный слой доступа к данным

**Этап:** 2. Данные и серверные инварианты

## Цель

Сосредоточить доступ к Supabase в Worker и обеспечить атомарные продуктовые инварианты.

## Контекст продукта

Браузер не должен получать service-role key или прямой доступ к базе.

## Объём

- Создать server-only Supabase client и репозитории доменных сущностей.
- Реализовать транзакционные операции создания, переходов статуса и записи результатов.
- Добавить пагинацию истории и аудита.
- Защитить запросы от межпользовательского доступа.

## Вне объёма

UI и вызовы REST API Битрикс24.

## Требования

- Только Workers используют service-role key.
- Ошибка записи одного результата не должна повреждать ранее записанные результаты.

## Критерии приёмки

- В клиентском коде отсутствует Supabase service-role client.
- Репозитории проверяют владельца или право просмотра всех данных.
- Конкурентные обновления не теряют счётчики и результаты.
- Интеграционные тесты проходят на отдельном development-проекте или локальном Supabase.

## Зависимости
