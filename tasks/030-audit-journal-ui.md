# 030. Реализовать интерфейс журнала аудита

**Этап:** 6. Отчёты, история и эксплуатационные процессы

## Цель

Дать пользователю с отдельным правом полный read-only обзор событий Task Commander.

## Контекст продукта

Право просмотра аудита открывает все события без ограничения подразделением.

## Объём

- Реализовать защищённый API списка аудита с пагинацией.
- Создать таблицу события с временем, пользователем, типом, объектом, результатом и связью.
- Добавить переход к связанной операции, отчёту или пользователю при наличии доступа.
- Представить системные ошибки безопасным текстом.

## Вне объёма

Редактирование, ручное удаление и выгрузка чувствительных технических данных.

## Требования

- Доступ предоставляет только отдельное право просмотра аудита.
- Экран и API не имеют mutation-действий над событиями.

## Критерии приёмки

- Уполномоченный пользователь видит события всех подразделений.
- Пользователь без права получает серверный отказ.
- Ссылки на объекты не обходят их собственные права доступа.
- Токены и защищённые значения отсутствуют в отображаемых полях.

## Зависимости

007, 010, 013.
