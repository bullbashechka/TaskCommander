# 035. Подключить production OAuth-адаптер и развернуть приложение

**Этап:** 7. Качество, безопасность и выпуск

## Цель

Развернуть готовую первую версию для одного облачного корпоративного портала Битрикс24.

## Контекст продукта

Production использует постоянный HTTPS-домен, OAuth redirect URI, Cloudflare Workers и Supabase PostgreSQL.

## Объём

- Реализовать `oauth`-адаптер задач, пользователей, структуры, календаря, уведомлений и Диска.
- Настроить production Supabase, Workers, Queue, Cron, R2, secrets и статические assets.
- Настроить домен, TLS, WAF, rate limiting и OAuth redirect URI.
- Применить миграции, выполнить smoke установки и текущего пользователя.
- Документировать деплой, rollback, ротацию secrets и эксплуатационные проверки.

## Вне объёма

Публикация в Маркет и поддержка нескольких порталов.

## Требования

- Webhook допускается только для диагностики, не для пользовательских операций.
- Production secrets задаются через Workers Secrets и не попадают в репозиторий.
- OAuth state является single-use, хранится server-side и имеет ограниченный срок жизни.
- Production sessions поддерживают server-side revocation; logout и отзыв доступа немедленно
  инвалидируют активную сессию.
- Session и confirmation tokens подписываются отдельными ключами. Каждый токен содержит `kid`, а
  bounded rotation допускает только документированное ограниченное окно предыдущего ключа.

## Критерии приёмки

- Приложение устанавливается и открывается внутри целевого портала по OAuth.
- Реальный пользователь, его активность и нативные права определяются корректно.
- Критический smoke выполняет поиск, безопасное тестовое изменение и создаёт отчёт на Диске.
- Мониторинг показывает Queue/Cron/Worker ошибки без раскрытия токенов.
- Повторное использование OAuth state и отозванной сессии отклоняется; тесты покрывают logout,
  access revocation, неизвестный `kid` и истечение rotation window.
- Ротация signing keys выполняется без общего ключа для session/confirmation и без бессрочного
  принятия старых подписей.
- Документированный rollback восстанавливает предыдущую рабочую версию и совместимую схему.
