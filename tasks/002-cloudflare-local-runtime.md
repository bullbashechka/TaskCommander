# 002. Настроить Cloudflare Workers и локальные bindings

**Этап:** 1. Основа проекта и локальный контур

## Цель

Создать локальный Cloudflare-контур, повторяющий production bindings без раскрытия секретов.

## Контекст продукта

Backend, Queue consumer, Cron и временное хранилище отчётов выполняются в Cloudflare.

## Объём

- Настроить Wrangler для API Worker и Queue consumer.
- Объявить Queue, R2, Cron и переменные окружения.
- Подготовить `.dev.vars.example` без реальных значений.
- Добавить проверку обязательной конфигурации при старте.

## Вне объёма

Создание production-ресурсов и настройка DNS/WAF.

## Требования

- `SUPABASE_URL`, service-role key и параметры Битрикс24 существуют только как серверные secrets.
- Development-отчёты используют локальную эмуляцию R2.

## Критерии приёмки

- Локально доступны API Worker, Queue consumer, тестовый Cron и R2 binding.
- Отсутствующий обязательный secret приводит к понятной серверной ошибке запуска.
- Клиентский bundle и API-ответы не содержат значений secrets.
- Конфигурация окружений описана в документации проекта.
