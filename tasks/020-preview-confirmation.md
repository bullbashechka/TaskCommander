# 020. Реализовать предварительный просмотр и подтверждение

**Этап:** 4. Поиск, выбор и подготовка массовой операции

## Цель

Показать точное воздействие операции и получить явное подтверждение пользователя.

## Контекст продукта

До запуска пользователь видит ID, название, ссылку, старые и новые значения, исключения и предупреждения.

## Объём

- Создать экран результатов preflight по каждой задаче.
- Показать допущенные и исключённые задачи с причинами.
- Добавить отдельный флажок осознанного запуска.
- Блокировать запуск при изменении данных проверки или параметров.
- Создавать серверный одноразовый токен подтверждения, привязанный к owner, ревизии черновика и точному snapshot preflight.

## Вне объёма

Постановка операции в очередь.

## Требования

- Кнопка запуска недоступна до подтверждения.
- Предыдущие значения для восстановления не раскрываются сверх текущего preview.

## Критерии приёмки

- Preview показывает старое и рассчитанное новое значение каждого изменяемого поля.
- Счётчик допущенных совпадает с данными preflight.
- Изменение выбора или параметров снимает подтверждение.
- Устаревший или чужой результат проверки нельзя подтвердить через API.
- Повторный HTTP-запрос того же подтверждения возвращает тот же токен, а изменённые входные данные отзывают его.
