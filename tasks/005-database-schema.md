# 005. Создать схему Supabase PostgreSQL и миграции

**Этап:** 2. Данные и серверные инварианты

## Цель

Создать версионируемую схему для минимальных технических данных Task Commander.

## Контекст продукта

Хранятся настройки, операции, результаты, отчёты и аудит; содержимое задач остаётся в Битрикс24.

## Объём

- Создать таблицы `UserSettings`, `BulkOperation`, `TaskProcessingResult`, `Report`, `AuditEvent` и личных фильтров.
- Добавить внешние ключи, индексы, ограничения статусов и временные метки.
- Учесть ссылки повтора/восстановления и сроки активного/архивного хранения.
- Добавить миграции и seed для development.

## Вне объёма

Supabase Auth, Storage, Edge Functions и хранение полных копий задач.

## Требования

- Предыдущие значения хранятся защищённо и отдельно от экспортируемых данных.
- Схема поддерживает результат каждой задачи независимо от результата операции.

## Критерии приёмки

- Миграции применяются к пустой базе и откатываются в тестовом контуре.
- Ограничения БД запрещают недопустимые статусы и оборванные связи.
- Основные запросы истории, прогресса и аудита используют индексы.
- Seed не содержит реальных данных или секретов Битрикс24.
