# Task Commander — дизайн интерфейса

## 1. Концепция

Task Commander — расширяемая внутренняя платформа, работающая внутри веб-версии Bitrix24. Массовое изменение задач является первым инструментом платформы, а не назначением всего продукта.

Интерфейс должен восприниматься как профессиональный рабочий центр: плотный, спокойный, предсказуемый и безопасный при выполнении массовых действий. Визуальная основа — тёмная навигационная панель из утверждённого референса и светлая рабочая область с компактными таблицами.

Основные принципы:

- универсальная оболочка не зависит от конкретного инструмента;
- каждый инструмент имеет собственную навигацию и рабочий процесс;
- таблицы являются основным способом работы с большими наборами данных;
- опасные или массовые действия всегда показывают масштаб и последствия;
- основной акцент используется только для текущего состояния и следующего действия;
- интерфейс остаётся на русском языке, название Task Commander не переводится.

## 2. Информационная архитектура

### 2.1. Общая оболочка

Левая панель содержит три уровня навигации.

1. Общий раздел:
   - Главная.
2. Инструменты:
   - Задачи;
     - Массовое изменение;
     - Операции;
     - Отчёты.
   - Данные.
3. Система:
   - Доступ;
   - Аудит.

В нижней части панели находятся общие настройки и профиль текущего пользователя.

«Задачи» — раскрываемая группа первого инструмента. «Данные» показывает модель расширения: новые функции добавляются как самостоятельные раскрываемые группы без изменения общей оболочки.

### 2.2. Границы навигации

- «Главная» показывает доступные пользователю инструменты, недавние операции и системные уведомления.
- «Массовое изменение» запускает основной сценарий поиска, выбора и обновления задач.
- «Операции» показывает историю запусков инструмента, их прогресс и результаты.
- «Отчёты» предоставляет созданные этим инструментом XLSX- и CSV-отчёты.
- «Доступ» управляет правами всей платформы.
- «Аудит» содержит общий журнал действий платформы.
- «Настройки» содержит параметры пользователя и общие настройки приложения.

Новые инструменты получают собственную группу и вложенные экраны. Общие системные разделы не дублируются внутри инструментов.

## 3. Каркас интерфейса

### 3.1. Рабочая область

Целевой формат первой версии — desktop web внутри Bitrix24. Базовый макет рассчитан на ширину 1440 пикселей.

- левая панель: 248 пикселей, фиксированная;
- рабочая область: занимает оставшуюся ширину;
- внутренние поля контента: 24–32 пикселя;
- верхняя область страницы содержит хлебные крошки, заголовок, пояснение и глобальные действия;
- таблица занимает основную высоту экрана;
- контекстная панель массового действия закрепляется у нижней границы рабочей области.

На ширине менее 1180 пикселей левая панель сворачивается до панели иконок. Горизонтальное содержимое таблицы прокручивается внутри рабочей области. Мобильная версия не входит в первую версию продукта.

### 3.2. Левая панель

Панель имеет тёмно-синий, почти чёрный фон. Активный вложенный пункт отображается на ярко-синей плашке с закруглением. Раскрытая группа получает направленный вверх шеврон и тонкую вертикальную линию, связывающую дочерние пункты.

Иерархия передаётся отступами:

- раздел — подпись прописными буквами;
- инструмент — строка с иконкой и шевроном;
- экран инструмента — вложенная строка без крупной иконки;
- системный раздел — самостоятельная строка с иконкой.

### 3.3. Верхняя часть страницы

Экран инструмента начинается с хлебных крошек «Инструменты / Задачи», заголовка «Массовое изменение задач» и пояснения «Поиск, выбор и безопасное обновление задач Bitrix24».

Справа располагаются глобальные элементы: уведомления и профиль пользователя. Они не относятся к текущему инструменту.

## 4. Экран массового изменения задач

### 4.1. Этапы сценария

Сценарий состоит из четырёх последовательных этапов:

1. Выбор задач.
2. Настройка изменений.
3. Проверка.
4. Выполнение.

Индикатор этапов располагается под заголовком. Текущий этап выделяется синим цветом. Пройденные этапы показывают подтверждённое состояние. Будущие этапы остаются нейтральными. Переход вперёд разрешён только после выполнения требований текущего этапа.

### 4.2. Панель поиска и фильтров

Панель располагается одной строкой над таблицей и содержит:

- область поиска: «Все незавершённые»;
- период: «Последние 30 дней»;
- кнопку фильтров со счётчиком активных условий;
- текстовый поиск по задачам;
- настройку столбцов или представления;
- основное действие «Настроить изменения».

Кнопка основного действия активна только при наличии выбранных задач. Сохранённые пользовательские фильтры открываются из первого элемента или отдельного меню внутри фильтрации.

### 4.3. Сводка выбора

При выборе хотя бы одной задачи над таблицей появляется светло-синяя информационная панель. Она показывает:

- точное число выбранных задач;
- общее число задач в текущей выборке;
- действие «Выбрать все» для всей отфильтрованной выборки;
- действие «Снять выбор».

Если фильтр соответствует более чем 1000 задачам, выбор всей выборки блокируется. Панель объясняет лимит и требует сузить фильтр.

Изменение фильтра очищает текущий выбор. Перед очисткой интерфейс показывает явное предупреждение, если выбраны задачи не только на текущей странице.

### 4.4. Таблица задач

Основные столбцы:

- выбор;
- задача;
- исполнитель;
- статус;
- приоритет;
- крайний срок;
- проект;
- контекстное меню.

Заголовок таблицы визуально отделён светло-серым фоном. Строки компактные, с высотой 48–52 пикселя. Длинные названия обрезаются в одну строку и полностью показываются во всплывающей подсказке.

Состояния передаются сочетанием текста и цвета:

- статус — мягкая цветная метка;
- приоритет — компактная метка;
- просроченный срок — красный текст и предупреждающая иконка;
- выбранная строка — синий флажок и лёгкий синий фон;
- недоступная задача — приглушённая строка с объяснением причины.

Нажатие на название открывает штатную карточку задачи Bitrix24. Контекстное меню содержит только действия, допустимые на этапе выбора.

### 4.5. Пагинация

Под таблицей показываются диапазон текущих строк, общее количество результатов, размер страницы и навигация по страницам. Выбор сохраняется между страницами одного результата фильтрации.

### 4.6. Закреплённая панель действия

После выбора задач у нижней границы рабочей области закрепляется панель, содержащая:

- число выбранных задач;
- напоминание о лимите 1000 задач;
- действие «Очистить»;
- основное действие «Настроить изменения».

Панель не перекрывает пагинацию и последнюю строку таблицы. На всех этапах она показывает действие, соответствующее следующему безопасному шагу.

## 5. Последующие этапы массовой операции

### 5.1. Настройка изменений

Экран использует две колонки:

- слева — список добавленных изменений;
- справа — форма выбранного поля и правила его изменения.

Каждое изменение представлено отдельным компактным блоком: поле, операция, новое значение и удаление настройки. Пользователь может добавить несколько разрешённых полей в одну операцию. Относительные изменения участников, тегов и дат явно отличаются от полной замены.

Нижняя панель показывает число задач, число изменяемых полей, действие возврата и основное действие «Проверить изменения».

### 5.2. Проверка

Экран показывает сводные показатели и таблицу предварительного просмотра:

- допущено к изменению;
- исключено из-за ошибок;
- обнаружены конфликты;
- текущие и новые значения по каждому изменяемому полю.

Ошибочные строки визуально отделяются и содержат конкретную причину. Запуск разрешён только для задач, прошедших проверку. Перед запуском интерфейс повторяет масштаб операции и состав изменений.

### 5.3. Выполнение

Экран содержит общий прогресс, счётчики результатов и поток последних событий. Основные состояния операции:

- подготовка;
- выполняется;
- отменяется;
- завершена;
- завершена частично;
- прервана;
- ошибка запуска.

Обновление страницы не создаёт повторную операцию. Во время выполнения доступны безопасная отмена и переход к деталям. После завершения доступны отчёт, повторный прогон неуспешных задач и восстановление предыдущих значений при наличии прав.

## 6. Главная страница платформы

Главная страница не копирует рабочий экран массового изменения. Она служит точкой входа в платформу и содержит:

- доступные пользователю инструменты;
- незавершённые и последние операции;
- ошибки, требующие внимания;
- системные уведомления;
- быстрый переход к последнему использованному инструменту.

Инструменты отображаются компактным списком или сеткой небольших карточек. Карточка содержит название, назначение и одно основное действие. Главная страница не превращается в аналитический дашборд без подтверждённой потребности.

## 7. Визуальная система

### 7.1. Цвета

Базовые токены:

| Назначение | Значение |
| --- | --- |
| Фон приложения | `#EEF1F5` |
| Рабочая поверхность | `#FFFFFF` |
| Фон боковой панели | `#0B1020` |
| Основной текст | `#111827` |
| Вторичный текст | `#667085` |
| Граница | `#E4E7EC` |
| Основной акцент | `#2F6BFF` |
| Светлый акцент | `#EEF4FF` |
| Успех | `#168A5B` |
| Предупреждение | `#D97706` |
| Ошибка | `#DC2626` |

Цвет не используется как единственный носитель смысла. Статусы сопровождаются текстом и при необходимости иконкой.

### 7.2. Типографика

Основной шрифт — системный sans-serif с характеристиками Inter. Рекомендуемый стек: `Inter, Arial, sans-serif`.

- заголовок страницы: 28–30 пикселей, 600–700;
- заголовок секции: 18–20 пикселей, 600;
- основной текст: 14 пикселей, 400–500;
- таблица: 13–14 пикселей;
- подписи разделов навигации: 11–12 пикселей, 500, прописные буквы;
- вспомогательный текст: 12–13 пикселей.

### 7.3. Геометрия

- базовый шаг сетки: 8 пикселей;
- малые отступы: 4 и 8 пикселей;
- стандартные отступы: 12, 16 и 24 пикселя;
- крупные интервалы: 32 и 40 пикселей;
- радиус полей и кнопок: 8 пикселей;
- радиус панелей: 10–12 пикселей;
- радиус основного контейнера: до 16 пикселей;
- высота стандартного контрола: 40–44 пикселя.

Тени используются только для закреплённых и всплывающих элементов. Основное разделение создают фон и тонкие границы.

### 7.4. Иконки

Используются единообразные контурные иконки размером 16–20 пикселей с толщиной линии 1,5–2 пикселя. Иконка без подписи допускается только для общеизвестного действия и получает всплывающую подсказку.

## 8. Состояния и обратная связь

Каждый экран предусматривает следующие состояния:

- начальная загрузка — скелетон, повторяющий структуру таблицы;
- пустой результат — причина и действие по изменению фильтра;
- отсутствие доступа — объяснение ограничения без показа закрытых данных;
- частичная ошибка — сохранение доступного результата и локальное сообщение;
- системная ошибка — идентификатор события для обращения к администратору;
- длительная операция — видимый прогресс без блокировки навигации;
- успешное действие — краткое подтверждение и доступ к результату.

Критические подтверждения оформляются модальным окном с конкретными числами и перечислением последствий. Для запуска массовой операции применяется явная кнопка «Запустить изменение», а не абстрактное «Продолжить».

## 9. Доступность

- минимальный контраст текста соответствует WCAG AA;
- все действия доступны с клавиатуры;
- фокус имеет заметный синий контур;
- область нажатия иконок составляет не менее 36×36 пикселей;
- таблица сохраняет логичный порядок фокуса;
- статусы и ошибки не кодируются только цветом;
- анимации короткие и функциональные, без обязательности для понимания состояния.

## 10. Правила расширения платформы

Новый инструмент добавляется без изменения базовой визуальной модели:

1. Получает пункт верхнего уровня в разделе «Инструменты».
2. При необходимости получает вложенные экраны.
3. Использует общие хлебные крошки, заголовок, профиль и уведомления.
4. Использует общие токены, контролы, таблицы, состояния и правила доступности.
5. Хранит собственные операции и отчёты внутри своей навигационной группы.
6. Передаёт события в общий аудит и использует общую систему доступа.

Название группы описывает предметную область, а дочерние пункты — конкретные действия или представления. В боковой панели одновременно раскрыта только текущая группа, чтобы рост числа инструментов не перегружал навигацию.

## 11. Зафиксированное направление

Утверждён гибридный подход:

- визуальная оболочка и плотность взяты из второго референса;
- светлая таблица остаётся главным рабочим объектом;
- тёмная боковая панель формирует устойчивую платформенную навигацию;
- массовое действие сопровождается пошаговым сценарием и закреплённой панелью;
- архитектура допускает добавление новых инструментов без переименования продукта и перестройки общей оболочки.

Первым реализуемым экраном является «Инструменты / Задачи / Массовое изменение». Его утверждённый макет служит эталоном для дальнейших экранов платформы.
