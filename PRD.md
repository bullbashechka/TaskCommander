# PRD: Task Commander

> **Связи с дизайном:** ссылки вида `Дизайн` указывают на реализацию соответствующих требований в [design.md](design.md) и предназначены для навигации и полнотекстового поиска.

## 1. Назначение продукта

> **Дизайн:** [§ 1 «Концепция»](design.md#1-концепция); [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 12 «Зафиксированное направление»](design.md#12-зафиксированное-направление).

Task Commander — внутреннее локальное приложение для облачного корпоративного Битрикс24. Приложение предоставляет сотрудникам единый инструмент для поиска незавершённых задач, выбора до 1 000 задач и безопасного массового изменения их параметров.

Приложение работает внутри веб-версии Битрикс24 и использует действующую учётную запись пользователя. Отдельная регистрация и отдельный вход отсутствуют.

Основная цель продукта — сократить количество ручных действий при однотипном изменении задач и обеспечить предварительную проверку, контролируемое выполнение, повторную обработку ошибок, восстановление предыдущих значений и полный аудит действий.

## 2. Целевые пользователи

### 2.1. Администратор Битрикс24

- автоматически получает полный доступ к Task Commander;
- назначает права любым сотрудникам компании;
- назначает отдельным руководителям право управления доступом;
- просматривает все операции, отчёты и события аудита;
- управляет разрешёнными для пользователей полями массового изменения.

### 2.2. Уполномоченный руководитель подразделения

- получает право управления доступом только после явного назначения администратором Битрикс24;
- выдаёт и отзывает права любым сотрудникам компании независимо от подразделения;
- назначает только те права, которыми обладает сам;
- автоматически теряет право управления доступом после утраты статуса руководителя;
- сохраняет остальные ранее назначенные права после утраты статуса руководителя.

### 2.3. Оператор

- работает только с задачами, доступными ему по штатным правам Битрикс24;
- использует только назначенные ему функции Task Commander;
- массово изменяет только разрешённые ему поля;
- просматривает и экспортирует отчёты в пределах назначенных прав.

## 3. Область первой версии

> **Дизайн:** [§ 1 «Концепция»](design.md#1-концепция); [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 3.1 «Рабочая область»](design.md#31-рабочая-область); [§ 12 «Зафиксированное направление»](design.md#12-зафиксированное-направление).

Первая версия включает:

- работу внутри одного облачного корпоративного Битрикс24;
- работу в веб-версии Битрикс24 на компьютере;
- интерфейс на русском языке;
- поиск и фильтрацию незавершённых обычных задач и подзадач;
- ручной выбор задач и выбор всех задач текущего фильтра;
- массовое изменение нескольких полей за одну операцию;
- относительное изменение дат, участников и тегов;
- предварительную проверку и просмотр изменений;
- выполнение операции с отображением прогресса;
- формирование отчётов;
- повторный прогон неуспешных задач;
- восстановление предыдущих значений;
- управление доступом и правами;
- журнал аудита;
- хранение отчётов на Диске Битрикс24.

## 4. Функциональные требования

### 4.1. Запуск и идентификация пользователя

> **Дизайн:** [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 3.3 «Верхняя часть страницы»](design.md#33-верхняя-часть-страницы).

1. Task Commander открывается внутри интерфейса корпоративного Битрикс24.
2. Пользователь определяется по текущей авторизованной сессии Битрикс24.
3. Отдельные учётные записи и пароли Task Commander не используются.
4. При каждом входе приложение проверяет активность пользователя, его штатные права Битрикс24 и права Task Commander.
5. Деактивированный или уволенный сотрудник не получает доступ к приложению.

### 4.2. Доступные задачи

1. Приложение получает только задачи, доступные текущему пользователю по штатным правам Битрикс24.
2. Права Task Commander не расширяют штатные права пользователя на задачи.
3. В приложение включаются обычные задачи и подзадачи.
4. Завершённые задачи полностью исключаются из поиска, просмотра, выбора и массового изменения.
5. Шаблоны задач и правила повторения не отображаются и не изменяются.
6. Повторяющийся экземпляр обрабатывается только как обычная незавершённая задача; правило его повторения не изменяется.

### 4.3. Поиск и фильтрация

> **Дизайн:** [§ 4.2 «Панель поиска и фильтров»](design.md#42-панель-поиска-и-фильтров); [§ 4.4 «Таблица задач»](design.md#44-таблица-задач); [§ 4.5 «Пагинация»](design.md#45-пагинация); [§ 11.4 «Таблицы и выбор задач»](design.md#114-таблицы-и-выбор-задач).

1. Приложение предоставляет все фильтры стандартного списка задач Битрикс24, применимые к незавершённым задачам.
2. Для каждого доступного массовому изменению поля задачи предоставляется соответствующий фильтр.
3. Для полей участников доступны отдельные условия по постановщику, исполнителю, соисполнителям и наблюдателям.
4. Набор операторов определяется типом поля:
   - текст: `содержит`, `не содержит`, `равно`, `не равно`, `заполнено`, `не заполнено`;
   - дата и время: `равно`, `до`, `после`, `диапазон`, `заполнено`, `не заполнено`;
   - число: `равно`, `не равно`, `больше`, `меньше`, `диапазон`, `заполнено`, `не заполнено`;
   - список и множественное поле: `включает`, `не включает`, `равно`, `не равно`, `заполнено`, `не заполнено`;
   - пользователь: `равно`, `не равно`, `включает`, `не включает`, `заполнено`, `не заполнено`;
   - логическое поле: `да` или `нет`.
5. Условия по разным полям объединяются логикой `И`.
6. Несколько выбранных значений одного поля объединяются логикой `ИЛИ`.
7. Пользователь сохраняет личные наборы фильтров, переименовывает их, применяет повторно и удаляет.
8. Сохранённые фильтры недоступны другим пользователям.
9. Список задач сортируется по одному выбранному полю по возрастанию или убыванию.
10. По умолчанию список сортируется по крайнему сроку по возрастанию.

### 4.4. Выбор задач

> **Дизайн:** [§ 4.3 «Сводка выбора»](design.md#43-сводка-выбора); [§ 4.4 «Таблица задач»](design.md#44-таблица-задач); [§ 4.5 «Пагинация»](design.md#45-пагинация); [§ 4.6 «Закреплённая панель действия»](design.md#46-закреплённая-панель-действия); [§ 11.4 «Таблицы и выбор задач»](design.md#114-таблицы-и-выбор-задач).

1. Пользователь выбирает отдельные задачи флажками.
2. Выбор сохраняется при переходе между страницами результатов одного фильтра.
3. Пользователь выбирает все задачи, соответствующие текущему фильтру.
4. Одна операция включает не более 1 000 задач.
5. Если фильтру соответствует более 1 000 задач, выбор всех блокируется. Приложение требует сузить фильтр.
6. Изменение фильтра после выбора очищает текущий выбор и требует сформировать его заново.
7. Перед переходом к настройке изменений приложение показывает точное количество выбранных задач.

### 4.5. Поля массового изменения

> **Дизайн:** [§ 5.1 «Настройка изменений»](design.md#51-настройка-изменений).

1. Приложение поддерживает все поля незавершённой задачи, которые текущая версия API Битрикс24 разрешает изменять, за исключением явно исключённых настоящим документом действий и полей.
2. Обязательный набор включает название, описание, постановщика, исполнителя, соисполнителей, наблюдателей, крайний срок, дату начала, приоритет, незавершённые статусы, проект или рабочую группу и теги.
3. Поле доступно пользователю только при одновременном выполнении трёх условий:
   - поле доступно для изменения через Битрикс24;
   - штатные права пользователя разрешают изменение конкретной задачи;
   - поле включено в персональный перечень разрешённых полей Task Commander.
4. Одна операция изменяет одно или несколько полей.
5. Для обычного изменения всем выбранным задачам назначается одинаковое новое значение поля.
6. Для множественных полей участников и тегов поддерживаются операции:
   - полная замена значений;
   - добавление указанных значений без удаления существующих;
   - удаление указанных значений без изменения остальных.
7. Для полей даты и времени поддерживаются:
   - установка фиксированного значения;
   - очистка значения, если Битрикс24 разрешает пустое значение;
   - сдвиг текущего значения вперёд или назад на заданное число дней.
8. При сдвиге даты пользователь выбирает календарные или рабочие дни.
9. Рабочие дни рассчитываются по производственному календарю Битрикс24.
10. При сдвиге даты сохраняется исходное время задачи.
11. Недопустимые сочетания значений блокируются предварительной проверкой.
12. Значение статуса `Завершена` недоступно для массовой установки.
13. Поля вложений и связанные с файлами действия недоступны для массового изменения.

### 4.6. Исключённые массовые действия

> **Дизайн:** [§ 5.1 «Настройка изменений»](design.md#51-настройка-изменений).

Task Commander не выполняет:

- массовое завершение задач;
- массовое удаление задач;
- добавление, изменение или удаление комментариев;
- добавление, замену или удаление файлов;
- изменение чек-листов;
- изменение шаблонов задач;
- изменение правил повторения;
- создание новых задач.

### 4.7. Предварительная проверка

> **Дизайн:** [§ 4.1 «Этапы сценария»](design.md#41-этапы-сценария); [§ 5.2 «Проверка»](design.md#52-проверка); [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь).

1. Перед подтверждением приложение повторно получает актуальные данные всех выбранных задач.
2. Для каждой задачи проверяются:
   - существование задачи;
   - незавершённый статус;
   - доступ пользователя;
   - право изменения задачи;
   - право изменения каждого выбранного поля;
   - допустимость новых значений;
   - наличие обязательных связанных данных;
   - соответствие ограничениям Битрикс24.
3. Задача, не прошедшая проверку, исключается из операции.
4. Для каждой исключённой задачи показывается причина.
5. Ошибки отдельных задач не блокируют запуск операции для остальных прошедших проверку задач.
6. Если проверку не прошла ни одна задача, запуск операции блокируется.
7. Задача, для которой все запрошенные значения уже установлены, получает результат `Изменения не требуются`, не передаётся на выполнение и не считается ошибкой проверки.

### 4.8. Предварительный просмотр и подтверждение

> **Дизайн:** [§ 4.1 «Этапы сценария»](design.md#41-этапы-сценария); [§ 5.2 «Проверка»](design.md#52-проверка); [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь).

1. Перед запуском приложение показывает:
   - ID, название и ссылку на каждую задачу;
   - текущие значения изменяемых полей;
   - рассчитанные новые значения;
   - перечень исключённых задач;
   - предупреждения и причины исключения;
   - итоговое количество задач, допущенных к обработке.
2. Пользователь устанавливает отдельный флажок подтверждения осознанного запуска.
3. Кнопка запуска недоступна до установки флажка.
4. Изменение параметров операции снимает подтверждение и требует повторной проверки.
5. Черновик подготовки сохраняется на 24 часа, не попадает в историю завершённых операций и восстанавливается только явным действием пользователя.
6. Каждый черновик имеет ревизию; устаревшая вкладка не может молча перезаписать более новую ревизию.

### 4.9. Выполнение операции

> **Дизайн:** [§ 5.3 «Выполнение»](design.md#53-выполнение); [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь).

1. Операция запускается только сразу после подтверждения.
2. Отложенный запуск и запуск по расписанию отсутствуют.
3. У одного пользователя одновременно выполняется не более одной операции.
4. Разные пользователи выполняют операции параллельно.
5. Непосредственно перед изменением каждой задачи приложение проверяет, не изменились ли после предварительного просмотра изменяемые поля, связанные ограничения, статус задачи или права пользователя.
6. Задача с изменившимися значимыми данными пропускается со статусом `Конфликт`; несвязанные изменения не блокируют операцию.
7. Ошибка одной задачи не останавливает обработку остальных задач.
8. Во время операции отображаются:
   - общее количество задач;
   - количество обработанных задач;
   - количество успешных задач;
   - количество задач с ошибками;
   - количество конфликтов;
   - количество оставшихся задач;
   - процент выполнения.
9. Пользователь отменяет активную операцию отдельным действием.
10. После отмены завершается обработка текущей задачи, новые задачи не запускаются.
11. При попытке закрыть приложение во время операции пользователь получает выбор: дождаться завершения или явно отменить операцию.
12. При потере соединения, закрытии браузера без подтверждения или аварийном завершении обработка прекращается после текущей задачи.
13. При отзыве доступа либо любого необходимого права инициатора операция прекращается после текущей задачи.
14. Для остановленной операции формируется частичный отчёт, включающий обработанные и необработанные задачи.
15. Повторное открытие приложения не запускает остановленную операцию автоматически.

### 4.10. Статусы операции и задачи

> **Дизайн:** [§ 5.3 «Выполнение»](design.md#53-выполнение); [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь).

Черновик подготовки имеет один из статусов:

- `Подготовка`;
- `Ожидает подтверждения`;

Запущенная операция имеет один из статусов:

- `Выполняется`;
- `Завершена`;
- `Завершена с ошибками`;
- `Отменена`;
- `Прервана`.

Результат обработки отдельной задачи имеет один из статусов:

- `Успешно`;
- `Ошибка`;
- `Конфликт`;
- `Исключена проверкой`;
- `Не обработана`;
- `Восстановлена`;
- `Ошибка восстановления`.
- `Изменения не требуются`;
- `Частично изменена`.

### 4.11. Итоговый отчёт

> **Дизайн:** [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 5.3 «Выполнение»](design.md#53-выполнение).

1. Отчёт формируется для каждой завершённой, отменённой или прерванной операции.
2. Отчёт содержит по каждой задаче:
   - ID задачи;
   - название;
   - ссылку в Битрикс24;
   - перечень изменённых полей;
   - результат обработки;
   - понятный текст ошибки или конфликта.
   - задачам, исключённым проверкой, и задачам без требуемых изменений соответствует отдельная строка без факта выполнения.
3. Карточка операции внутри Task Commander дополнительно содержит:
   - идентификатор операции;
   - тип операции;
   - инициатора;
   - дату и время начала;
   - дату и время завершения;
   - количество выбранных, исключённых, успешных, ошибочных, конфликтных и необработанных задач.
4. Предыдущие значения, необходимые для восстановления, сохраняются в защищённой записи операции внутри Битрикс24 и не выводятся в экспортируемый отчёт.
5. Отчёт является минимальным историческим снимком: не содержит описания, участников, файлов, предыдущих или новых значений полей. Если задача недоступна уже при проверке, вместо названия и ссылки выводится нейтральная строка без закрытых данных.
6. Отчёт доступен внутри приложения пользователям с правом просмотра собственного либо всех отчётов.
7. Для каждой операции автоматически создаются файлы XLSX и CSV.
8. Файлы сохраняются на общем Диске компании в папке `Task Commander`.
9. Пользователь получает доступ к файлу только при одновременном наличии:
   - права просмотра соответствующего отчёта;
   - права экспорта отчётов.
10. Ошибка создания одного формата не блокирует создание другого формата и фиксируется в аудите.
11. Ошибка сохранения файлов на Диск не изменяет результат операции над задачами; отчёт остаётся доступен внутри приложения.

### 4.12. Повторный прогон

> **Дизайн:** [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 5.3 «Выполнение»](design.md#53-выполнение).

1. Повторный прогон является отдельной операцией и требует отдельного права.
2. В повторный прогон включаются все задачи исходного отчёта со статусами `Ошибка`, `Конфликт` и `Не обработана`, а для частично изменённой задачи — только неприменённые поля.
3. Перед повторным прогоном приложение заново получает задачи, проверяет права и допустимость изменений.
4. Пользователь получает новый предварительный просмотр и повторно подтверждает запуск.
5. Успешно обработанные задачи исходной операции в повторный прогон не включаются.
6. Повторный прогон создаёт отдельный отчёт со ссылкой на исходную операцию.
7. Количество ручных повторных прогонов не ограничивается в пределах срока активного хранения исходной операции.

### 4.13. Восстановление предыдущих значений

> **Дизайн:** [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 5.3 «Выполнение»](design.md#53-выполнение).

1. Восстановление является отдельной массовой операцией и требует отдельного права.
2. Восстановление доступно в течение одного года с момента исходной операции.
3. Пользователь выбирает все либо отдельные успешно или частично изменённые задачи исходной операции; для частичного изменения доступны только реально применённые поля.
4. Приложение использует сохранённые предыдущие значения только тех полей, которые меняла исходная операция.
5. Перед восстановлением выполняются новая проверка, предварительный просмотр и подтверждение.
6. Если после исходной операции задачу изменил другой пользователь или другой процесс, задача пропускается со статусом `Конфликт`.
7. Восстановление не перезаписывает последующие изменения.
8. Восстановление выполняется только при наличии актуальных штатных прав Битрикс24, права запуска, права восстановления и права изменения соответствующих полей.
9. Восстановление создаёт отдельный отчёт со ссылкой на исходную операцию.
10. Восстановление не применяется к действиям, исключённым из первой версии.

### 4.14. История операций

> **Дизайн:** [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 5.3 «Выполнение»](design.md#53-выполнение).

1. История содержит собственные операции пользователя либо все операции в зависимости от назначенного права.
2. История фильтруется по:
   - дате;
   - инициатору;
   - типу операции;
   - результату.
3. Активная история и отчёты хранятся один год.
4. В течение активного периода доступны просмотр, повторный прогон и восстановление в пределах прав пользователя.
5. Через один год отчёты переносятся в папку `Task Commander/Архив` на Диске Битрикс24.
6. Раздел `Архив` внутри Task Commander отображает индекс архивных отчётов, но содержимое отчёта читает непосредственно с Диска Битрикс24.
7. Архивные отчёты доступны только для просмотра и экспорта в пределах назначенных прав.
8. Через один год после архивации отчёты и их архивный индекс удаляются.
9. Общий срок хранения отчёта составляет два года.

### 4.15. Уведомления

> **Дизайн:** [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 6 «Главная страница платформы»](design.md#6-главная-страница-платформы); [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь).

1. После завершения, отмены или прерывания операции инициатор получает уведомление в центре уведомлений Битрикс24.
2. Уведомление содержит тип операции, итоговый статус, количество успешных и неуспешных задач и ссылку на отчёт.
3. Штатные уведомления Битрикс24 участникам изменяемых задач сохраняются без изменений.
4. Сотрудник получает уведомление Битрикс24 при выдаче доступа, изменении прав и отзыве доступа к Task Commander.

### 4.16. Управление доступом

> **Дизайн:** [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 10 «Правила расширения платформы»](design.md#10-правила-расширения-платформы).

Для пользователя независимо назначаются следующие права:

1. Вход и просмотр задач.
2. Запуск массовых операций.
3. Изменение разрешённых полей с персональным перечнем полей.
4. Повторный прогон.
5. Восстановление предыдущих значений.
6. Просмотр собственных отчётов.
7. Просмотр всех отчётов.
8. Экспорт отчётов.
9. Просмотр журнала аудита.
10. Управление доступом.

Правила назначения:

1. Все администраторы Битрикс24 автоматически получают полный набор прав и доступ ко всем полям.
2. Права администратора Битрикс24 нельзя ограничить средствами Task Commander.
3. Право управления доступом руководителю назначает администратор Битрикс24.
4. Пользователь с правом управления доступом назначает права любому сотруднику компании.
5. Такой пользователь назначает другому сотруднику только права, которыми обладает сам.
6. Перечень разрешённых полей получателя не превышает перечень полей назначающего пользователя.
7. Права действуют бессрочно до ручного или автоматического отзыва.
8. Временные права и дата окончания доступа отсутствуют.
9. При деактивации или увольнении сотрудника все его права автоматически отзываются; история действий сохраняется.
10. При утрате статуса руководителя автоматически отзывается только право управления доступом.
11. Для повторного прогона или восстановления чужой операции одновременно требуются право просмотра всех отчётов и соответствующее право действия.

### 4.17. Журнал аудита

> **Дизайн:** [§ 2.1 «Общая оболочка»](design.md#21-общая-оболочка); [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 10 «Правила расширения платформы»](design.md#10-правила-расширения-платформы).

1. Журнал фиксирует:
   - создание, запуск, завершение, отмену и прерывание операций;
   - повторные прогоны;
   - восстановления;
   - выдачу, изменение и отзыв доступа;
   - изменение перечня разрешённых полей;
   - экспорт и скачивание отчётов;
   - автоматический отзыв прав;
   - ошибки сохранения отчётов;
   - системные ошибки выполнения операций.
2. Каждая запись содержит дату и время, пользователя, тип действия, объект действия, результат и технический идентификатор связи.
3. Пользователь с правом просмотра аудита видит все события Task Commander без ограничения по подразделению.
4. Журнал доступен только для чтения.
5. Записи аудита нельзя изменять или удалять вручную.
6. Срок хранения журнала аудита составляет два года.

## 5. Основные пользовательские сценарии

### 5.1. Массовое изменение задач

> **Дизайн:** [§ 4 «Экран массового изменения задач»](design.md#4-экран-массового-изменения-задач); [§ 5 «Последующие этапы массовой операции»](design.md#5-последующие-этапы-массовой-операции).

1. Пользователь открывает Task Commander.
2. Приложение проверяет права.
3. Пользователь задаёт фильтры и получает список незавершённых задач.
4. Пользователь выбирает отдельные задачи либо все задачи текущего фильтра.
5. Пользователь задаёт одно или несколько изменений.
6. Приложение выполняет предварительную проверку.
7. Пользователь просматривает текущие и новые значения и исключённые задачи.
8. Пользователь подтверждает операцию флажком и запускает её.
9. Приложение показывает ход выполнения.
10. Приложение формирует отчёт, сохраняет XLSX и CSV на Диск и отправляет уведомление.

### 5.2. Повторный прогон

> **Дизайн:** [§ 5.3 «Выполнение»](design.md#53-выполнение).

1. Пользователь открывает отчёт исходной операции.
2. Приложение формирует набор из ошибочных, конфликтных и необработанных задач.
3. Приложение повторно проверяет задачи и рассчитывает изменения.
4. Пользователь подтверждает новую операцию.
5. Приложение выполняет повторный прогон и создаёт отдельный отчёт.

### 5.3. Восстановление

> **Дизайн:** [§ 5.3 «Выполнение»](design.md#53-выполнение).

1. Пользователь открывает активный отчёт возрастом не более одного года.
2. Пользователь выбирает все либо отдельные успешно изменённые задачи.
3. Приложение сравнивает актуальное состояние задач с состоянием после исходной операции.
4. Задачи с последующими изменениями исключаются как конфликты.
5. Пользователь просматривает восстанавливаемые значения и подтверждает операцию.
6. Приложение восстанавливает допустимые задачи и формирует отдельный отчёт.

### 5.4. Управление доступом

> **Дизайн:** [§ 2.2 «Границы навигации»](design.md#22-границы-навигации); [§ 10 «Правила расширения платформы»](design.md#10-правила-расширения-платформы).

1. Администратор либо уполномоченный руководитель открывает управление доступом.
2. Выбирает сотрудника.
3. Назначает доступные ему права и разрешённые поля.
4. Приложение проверяет, что назначающий пользователь не передаёт отсутствующие у него права.
5. Изменение сохраняется, фиксируется в аудите и отправляется сотруднику через уведомления Битрикс24.

## 7. Интеграции Битрикс24

Приложение использует следующие сервисы корпоративного Битрикс24:

- задачи — поиск, чтение и изменение задач;
- пользователи и структура компании — идентификация, проверка активности и статуса руководителя;
- права доступа — соблюдение штатных ограничений пользователя;
- производственный календарь — расчёт рабочих дней;
- центр уведомлений — сообщения о результатах операций и изменениях доступа;
- Диск — создание папок, сохранение, чтение, архивация и удаление отчётов.

Портал должен использовать коммерческий тариф Битрикс24 с доступными REST API и Диском.

## 8. Нефункциональные требования

> **Дизайн:** [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь); [§ 9 «Доступность»](design.md#9-доступность); [§ 11 «Реализация интерфейса»](design.md#11-реализация-интерфейса).

### 8.1. Производительность

> **Дизайн:** [§ 11.4 «Таблицы и выбор задач»](design.md#114-таблицы-и-выбор-задач).

1. Приложение рассчитано на портал с общим объёмом до 100 000 задач.
2. Приложение поддерживает до 20 одновременно работающих пользователей.
3. Первый экран результатов фильтра загружается не более чем за 5 секунд в целевом режиме и не более чем за 10 секунд при предельной штатной нагрузке.
4. Операция из 1 000 задач завершается не более чем за 15 минут при штатной доступности API Битрикс24.
5. Длительные действия сопровождаются видимым состоянием загрузки или прогресса.

### 8.2. Надёжность

1. Повторное нажатие запуска, обновление страницы или повторная доставка одного запроса не создают дублирующую операцию.
2. Результат изменения каждой задачи фиксируется отдельно.
3. Частичный сбой не уничтожает результаты уже обработанных задач.
4. Отчёт формируется для любого конечного состояния операции.
5. Ограничения частоты запросов Битрикс24 соблюдаются без потери задач.

### 8.3. Безопасность

1. Все действия выполняются от имени текущего пользователя Битрикс24 и в пределах его штатных прав.
2. Права Task Commander только ограничивают доступ и никогда не расширяют права Битрикс24.
3. Содержимое задач не хранится вне Битрикс24.
4. Вне Битрикс24 хранятся только минимальные технические данные, необходимые для безопасной работы приложения.
5. Токены доступа и технические идентификаторы не выводятся в интерфейс, отчёты и аудит.
6. Отчёты на Диске получают индивидуальные права согласно правам просмотра и экспорта.
7. Предыдущие значения для восстановления доступны только механизму восстановления и пользователям с соответствующими правами.
8. Все операции изменения, экспорта и управления доступом фиксируются в аудите.

### 8.4. Совместимость

> **Дизайн:** [§ 3.1 «Рабочая область»](design.md#31-рабочая-область); [§ 11.1 «Базовые технологии»](design.md#111-базовые-технологии); [§ 11.5 «Темы и доступность»](design.md#115-темы-и-доступность).

1. Поддерживается актуальная веб-версия облачного Битрикс24 для компьютера.
2. Поддерживаются браузеры, официально поддерживаемые Битрикс24.
3. Мобильные браузеры и мобильное приложение Битрикс24 не входят в требования первой версии.

### 8.5. Технологический стек и инфраструктура

> **Технический дизайн:** [Task Commander — технический дизайн первого этапа](docs/superpowers/specs/2026-08-06-task-commander-design.md).

1. Клиентское приложение реализуется на React, Vite и TypeScript с TanStack Router, Query, Table и Form; визуальная система — Tailwind CSS v4, Base UI, shadcn/ui и Sonner.
2. API и BFF реализуются на Hono в Cloudflare Workers. Workers обслуживают API и статические assets клиентского приложения; локальная разработка и deployment выполняются через Wrangler.
3. Постоянные данные приложения хранятся в Supabase PostgreSQL. Схема, SQL-функции и миграции управляются через Supabase CLI. Supabase Auth, Storage и Edge Functions не используются.
4. Серверный доступ к Supabase выполняется только из Cloudflare Workers через service-role key. URL Supabase, service-role key и секреты Bitrix24 хранятся в Cloudflare Workers Secrets и не передаются в браузер.
5. Подтверждённые массовые операции доставляются через Cloudflare Queues в отдельный Worker consumer. Consumer фиксирует результат каждой задачи, соблюдает ограничения API Битрикс24 и обеспечивает идемпотентность операции.
6. Cloudflare Cron Triggers запускают повторную обработку временных ошибок и проверку зависших операций.
7. Cloudflare R2 используется только для временного хранения сформированных отчётов до их загрузки в Bitrix24 Disk.
8. Публичный endpoint защищается средствами Cloudflare DNS, TLS, WAF и rate limiting.

## 9. Критерии готовности первой версии

> **Дизайн:** [§ 4 «Экран массового изменения задач»](design.md#4-экран-массового-изменения-задач); [§ 5 «Последующие этапы массовой операции»](design.md#5-последующие-этапы-массовой-операции); [§ 8 «Состояния и обратная связь»](design.md#8-состояния-и-обратная-связь); [§ 9 «Доступность»](design.md#9-доступность); [§ 11 «Реализация интерфейса»](design.md#11-реализация-интерфейса).

Первая версия считается готовой, если одновременно выполняются все условия:

1. Пользователь входит в Task Commander через действующую сессию Битрикс24.
2. Приложение не показывает завершённые или недоступные пользователю задачи.
3. Фильтры, сортировка и сохранение личных фильтров работают в соответствии с настоящим документом.
4. Пользователь выбирает отдельные задачи или весь результат до 1 000 задач.
5. Пользователь изменяет несколько разрешённых полей одной операцией.
6. Предварительный просмотр показывает текущие и новые значения каждой допущенной задачи.
7. Задачи с ошибками предварительной проверки исключаются до запуска.
8. Изменившиеся после предварительного просмотра задачи не перезаписываются.
9. Ошибка отдельной задачи не останавливает остальные задачи.
10. Отмена и аварийное прерывание создают корректный частичный отчёт.
11. Повторный прогон обрабатывает все неуспешные категории задач после новой проверки.
12. Восстановление возвращает предыдущие значения и не перезаписывает последующие изменения.
13. XLSX- и CSV-отчёты сохраняются на общем Диске с корректными правами.
14. Активное и архивное хранение соблюдает срок два года.
15. Система прав не позволяет пользователю назначить отсутствующее у него право или поле.
16. Деактивация сотрудника автоматически отзывает доступ.
17. Журнал аудита содержит все предусмотренные события и доступен только пользователям с отдельным правом.
18. Выполняются установленные требования по производительности, надёжности и безопасности.
