# Task Commander — технический дизайн первого этапа

## Контекст и границы

Task Commander — локальное встраиваемое приложение одного облачного портала Bitrix24. Оно позволяет искать незавершённые задачи, выбрать до 1 000 задач и безопасно выполнить массовое изменение разрешённых полей.

Первый этап охватывает локальную настройку и запуск. Публичный сайт, мобильное приложение, платежи и production-деплой отложены.

## Архитектура

Основа — репозиторий `di-sukharev/vibe`, адаптированный под Cloudflare и Supabase. Активны поверхности `webapp` и `backend`.

- `webapp`: React, Vite, TypeScript, TanStack Router/Query/Table/Form, Tailwind CSS v4, Base UI, shadcn/ui и Sonner. Приложение отображается внутри Bitrix24.
- `backend`: Hono в Cloudflare Workers. BFF изолирует вызовы REST API Bitrix24, OAuth-сессию, разрешения, запуск операций, генерацию отчётов и аудит. Локальная разработка использует Bun и Cloudflare Vite plugin; deployment выполняется через Wrangler.
- Supabase PostgreSQL: постоянное хранилище операций, результатов обработки, аудита, личных фильтров и метаданных отчётов. Схема и SQL-функции мигрируются Supabase CLI; Prisma не используется.
- Supabase server client: единственная серверная точка доступа к данным через service-role key из Cloudflare Workers Secrets. Supabase Auth, Storage и Edge Functions не входят в архитектуру.
- Cloudflare Queues: доставляет подтверждённые массовые операции в Worker consumer. Consumer применяет изменения в Bitrix24, сохраняет результат каждой задачи и использует идемпотентный ключ операции.
- Cloudflare Cron Triggers: запускает повторную обработку временных ошибок и проверку зависших операций.
- Cloudflare R2: временно хранит сформированные отчёты; финальный отчёт выгружается в Bitrix24 Disk.
- Bitrix24 adapter: единый интерфейс для задач, пользователей, прав, уведомлений и Disk. Реализация `mock` используется локально до создания приложения Bitrix24; реализация `oauth` подключается позднее.

Публичная Astro-поверхность (`website`) и ветка Expo (`mobile`) остаются в репозитории, но не настраиваются и не валидируются на первом этапе.

## Аутентификация и доступ

Пользователь определяется OAuth-контекстом локального приложения Bitrix24. Стандартная JWT-аутентификация шаблона не используется.

Права Task Commander дополняют, но не расширяют нативные права Bitrix24. Backend проверяет активность пользователя, назначенные права приложения и доступ к каждой обрабатываемой задаче.

Вебхук допускается только как технический инструмент диагностики Bitrix24 API. Он не используется для пользовательской авторизации или выполнения пользовательских операций.

## Вертикальный срез

Первый функциональный срез реализует последовательность:

1. Серверный поиск, фильтрация, сортировка и пагинация незавершённых задач.
2. Выбор отдельных задач или всего результата — не более 1 000.
3. Настройка массового изменения разрешённых полей.
4. Предварительная проверка с отображением старых и новых значений, исключений и ошибок.
5. Подтверждённый запуск с прогрессом, результатами по задачам и аудитом.

Восстановление значений, повторный прогон ошибок, отчёты на Bitrix24 Disk и делегирование прав строятся поверх этой модели в следующих срезах.

## Модель данных

- `UserSettings`: настройки пользователя, разрешённые поля и личные фильтры.
- `BulkOperation`: инициатор, параметры, этап, идемпотентность и сводный статус.
- `TaskProcessingResult`: результат изменения отдельной задачи, снимок значений и ошибка при наличии.
- `Report`: формат, расположение, права и срок хранения.
- `AuditEvent`: неизменяемая запись о значимом действии.

## Локальный запуск и будущий деплой

Локальный запуск использует Wrangler и локальные Cloudflare bindings. Для интеграционной проверки Supabase используется отдельный development-проект или локальный Supabase CLI; его service-role key хранится только в локальном `.dev.vars`. Отчёты development-режима хранятся в локальной эмуляции R2; в production они временно размещаются в R2 и выгружаются в Bitrix24 Disk.

Поддерживаемый путь deployment: Cloudflare Workers обслуживает API и статические assets webapp; Supabase предоставляет PostgreSQL. Cloudflare DNS, TLS, WAF и rate limiting защищают публичный endpoint. Для запуска внутри Bitrix24 потребуется постоянный HTTPS-домен и OAuth redirect URI. `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` и параметры Bitrix24 задаются через Cloudflare Workers Secrets и никогда не передаются в браузер.

## Проверка

В локальном контуре проверяются typecheck, проверки границ Worker-кода, SQL-миграции Supabase, обработчик Cloudflare Queue и E2E критического сценария с mock-адаптером Bitrix24. После подключения OAuth дополнительно проверяются установка приложения, получение текущего пользователя и работа прав Bitrix24.
