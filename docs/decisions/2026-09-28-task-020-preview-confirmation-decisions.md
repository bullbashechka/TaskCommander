# Решения задачи 020: просмотр и подтверждение

## Граница сценария

- После сохранения актуальной версии черновика UI вызывает preflight и показывает допущенные,
  исключённые и не требующие изменений задачи отдельно. Для доступных значений выводятся исходное
  и рассчитанное новое значение каждого выбранного поля. Скрытые preflight сведения не дополняются
  данными из черновика или поиска.
- Подтверждение требует флажка и отдельного модального действия. На этом этапе оно только создаёт
  серверный токен. Запуск операции и расходование токена относятся к задаче 021. Нулевой допустимый
  набор не выдаёт токен; нейтральный итог без Queue остаётся требованием задачи 021.

## Серверная привязка и актуальность

- `POST /api/tasks/preflight/confirm` принимает только ID черновика, ревизию и время проверки.
  Сервер берёт весь snapshot из принадлежащего пользователю черновика, сверяет его форму и связь с
  выбором, повторно проверяет доступ и вызывает атомарный RPC. Клиент не может подменить записи,
  значения или счётчики.
- RPC блокирует черновик и проверяет владельца, статус, ревизию, версию доступа, точное JSONB
  равенство snapshot и срок проверки. Подтверждение допустимо 15 минут от `checkedAt`, но не дольше
  срока черновика. Для небольшого расхождения часов Worker и базы допускается минута в будущем.
- Таблица хранит токен UUID, ревизию, SHA-256 отпечаток сохранённого snapshot, срок и время
  расходования. Снимок повторно в таблице не хранится. Точный HTTP-повтор возвращает прежний токен;
  расходованный токен не выдаётся повторно. Изменение ревизии или snapshot черновика удаляет
  подтверждение в той же транзакции. Задача 021 обязана расходовать токен атомарно при создании
  операции и повторить проверку снимка, ревизии, владельца, срока и доступа.
- Запрос с неверным `checkedAt` возвращает конфликт и не отзывает уже выданный токен: он не меняет
  входные данные черновика. Отзыв происходит при фактическом изменении ревизии или снимка, чтобы
  ошибочный запрос из другой вкладки не мог отменить действительное подтверждение.

## Инвалидация в интерфейсе

- Проверка начинается только после сохранения формы. Если форма изменилась во время запроса,
  поздний ответ не открывает preview, но серверная ревизия результата учитывается для следующего
  сохранения. Если ответ preflight потерян, клиент повторяет тот же запрос по сохранённой ревизии;
  сервер возвращает точный ранее записанный снимок. При неопределённом ответе сохранения клиент
  сверяет принадлежащий пользователю черновик по ревизии, статусу и полному содержимому до
  продолжения. Несовпадение требует обновить черновик, без применения чужих изменений.
- Возврат к настройке, изменение доступа или сессии и повторная проверка снимают локальный флажок.
  Истечение срока по времени сервера блокирует API, а локальный таймер закрывает модальное окно и
  сбрасывает подтверждение. Конфликт другой вкладки отклоняет серверная проверка ревизии.
