# Решения реализации: задача 008

Дата: 2026-08-11  
Статус: утверждено  
Текущая задача: **008. Реализовать машину состояний и идемпотентность операций**.

## Зафиксированные правила

1. Точный технический повтор создания возвращает ту же операцию. Тот же ключ с другим
   подтверждённым содержимым отклоняется.
2. Активная операция имеет приоритет. Новый черновик сохраняется, но запуск блокируется
   до нового preflight и подтверждения.
3. Отмена является запросом остановки. Если запрос принят до финализации, итоговый статус
   становится `cancelled`, а уже сохранённые результаты и ошибки остаются в счётчиках. Запрос
   после перехода в терминальный статус ничего не меняет.
4. Конечный статус вычисляет база по результатам и первой причине остановки.
5. Терминальная операция и её результаты неизменяемы. Допустим только точный повтор
   уже сохранённого результата.
6. Нулевая операция завершается синхронно без Queue.
7. Неправильная команда не меняет состояние и записывает один системный аудит-событие.
8. Полная потеря прав прерывает операцию; недоступность одной задачи относится только к
   этой задаче. Реальная классификация ошибок Битрикс24 относится к задаче 022.
9. Task Commander не повторяет неопределённый `tasks.task.update` вслепую. Перед
   повтором будущий consumer перечитывает задачу через MCP Bitrix24.
10. Подтверждённый набор нельзя расширять во время выполнения: поздняя проверка может
    только исключить задачу.
11. Подтверждение получает server-side токен, привязанный к конкретным черновику, ревизии
    и preflight. Двойной клик, обновление и вторая вкладка возвращают ту же операцию.
12. Операция не зависит от вкладки: закрытие браузера и потеря пользовательской сети не
    останавливают серверную обработку. Lease относится только к consumer-у.
13. При потере ответа после изменения задачи результат становится `unconfirmed`. Изменение
    не повторяется без перечитывания задачи и сравнения с исходным и ожидаемым состоянием.
14. Позднее подтверждение создаёт отдельное неизменяемое уточнение. Оно не переписывает
    исходный результат, итоговый статус, счётчики или ранее сформированный отчёт.
15. Прогресс показывает долю задач с окончательным результатом. Успешность показывается
    отдельными счётчиками; серверная `stateVersion` не позволяет UI применить устаревший ответ.
16. Передача Queue и результат задачи содержат номер попытки и отпечаток содержимого.
    Точный повтор является no-op; отличающийся повтор отклоняется и фиксируется в аудите.
17. Отмена ограниченно ожидает уже начатую задачу и может только уточнить её фактический
    итог. Обычный повтор изменения после отмены не выполняется.
18. Частично применённая задача повторяет только неприменённые поля, а восстановление
    использует только реально применённые поля.
19. Для конфликта сравниваются только изменяемые поля, права и связанные ограничения.
    Несвязанные изменения задачи не создают конфликт.

## Граница задачи

Задача 008 создаёт SQL-инварианты, RPC и серверные типы, включая `stateVersion`,
`launchAttempt`, `unconfirmed` и append-only уточнение результата. Queue, UI отмены,
server-side lease, cron-восстановление, версии файлов отчётов и обращения к Битрикс24
остаются в задачах 020–026, 028 и 031.
