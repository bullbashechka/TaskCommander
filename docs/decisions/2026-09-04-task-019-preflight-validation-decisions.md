# Решения задачи 019: предварительная проверка задач

## Граница операции

- `POST /api/tasks/preflight` принимает только идентификатор черновика и ожидаемую ревизию.
  Выбор задач, фильтры, сортировка и команды читаются из принадлежащего пользователю серверного
  черновика и повторно проверяются по актуальному каталогу полей.
- Проверка не изменяет задачи и не создаёт операцию. Интерфейс просмотра и подтверждение относятся
  к задаче 020, создание операции — к задаче 021, повторная проверка непосредственно перед записью —
  к задаче 022.
- Нулевой допустимый набор сохраняется с `canProceed: false`. Задача 019 блокирует продолжение, но не
  создаёт синхронную нулевую операцию.

## Классификация и внешние сбои

- Каждая выбранная задача получает один результат в исходном порядке: `eligible`,
  `excluded_by_preflight` или `no_change`.
- Недоступная, отсутствующая, завершённая задача, шаблон и правило повторения исключаются нейтрально,
  без раскрытия названия и ссылки. Экземпляр регулярной задачи остаётся обычной изменяемой задачей.
- Отсутствие права на любое выбранное поле исключает задачу целиком до определения `no_change`.
  Частичное изменение одной задачи не подготавливается.
- Неизвестный пользователь, неактивный участник или недоступный целевой проект в полном рассчитанном
  значении исключает задачу. Проверка проекта выполняется отдельным пакетным методом адаптера.
- Для дат адаптер возвращает обе стороны пары `start_date`/`deadline`, даже если изменяется только одна.
  Preflight проверяет итоговую комбинацию и отдельно учитывает управление крайним сроком родителя
  подзадачами.
- Ошибки аутентификации, rate limit, временная недоступность, повреждённый ответ задачи, календаря или
  справочника пользователей прерывают весь preflight. Они не преобразуются в предметные исключения,
  чтобы временный сбой не создавал обманчиво суженный набор задач.
- Новые связанные сущности и межполевые правила нельзя добавлять в каталог изменений без расширения
  read-only контракта адаптера и соответствующей проверки preflight; `editableFieldIds` не считается
  заменой предметной валидации.

## Снимок и конкурентность

- Для допустимых задач и `no_change` сохраняются актуальные исходные и абсолютные целевые значения,
  точный список изменившихся полей и `relevantVersion`. Относительные даты вычисляются один раз по
  снимку календаря портала.
- Результат связан с идентификатором и ревизией черновика, пользователем через owner-scoped доступ к
  строке и версией effective access. После внешних чтений доступ проверяется повторно.
- Отдельный SQL RPC блокирует черновик, повторно проверяет владельца, срок, ревизию, состояние и
  серверную версию доступа, затем атомарно переводит черновик в `awaiting_confirmation`. Точный повтор
  после потерянного HTTP-ответа возвращает уже сохранённый снимок без увеличения ревизии.
- Изменение черновика очищает снимок существующим путём сохранения. Несовпавшая ревизия или версия
  доступа даёт конфликт.

## Ограничения ресурсов и хранения

- Чтения задач и справочника пользователей выполняются с ограниченной конкурентностью, результаты
  сохраняют порядок выбора. Вызов endpoint ограничен по клиенту и паре портал/пользователь.
- Приложение отклоняет сериализованный снимок больше 7 000 000 байт; RPC независимо отклоняет JSONB
  больше 8 MiB.
- Полный preflight-снимок предназначен для короткоживущего черновика. Задача 021 не должна бессрочно
  копировать открытые исходные значения в операцию; долговременные предыдущие значения должны
  храниться только в защищённом формате, утверждённом для результатов выполнения.
