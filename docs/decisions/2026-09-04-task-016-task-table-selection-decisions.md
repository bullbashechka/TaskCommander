# Решения реализации: задача 016

Дата: 2026-09-04
Статус: реализовано

## Таблица и локальный выбор

- Таблица использует стабильный ID задачи Bitrix24 как идентификатор строки. Выбранные ID хранятся
  отдельно от данных текущей страницы, поэтому ручной выбор сохраняется при пагинации и изменении
  размера страницы.
- Интерфейс различает ручной выбор и подтверждённый сервером выбор всего результата. Ручное
  добавление строки и страницы во всех случаях ограничено 1 000 уникальными ID.
- Изменение любого условия фильтра очищает выбор. Если выбор содержит строки с других страниц,
  очистка требует явного подтверждения; выбор только на текущей странице очищается сразу.
  Пагинация, размер страницы и сортировка сохраняют выбор, поскольку не меняют множество задач,
  соответствующих фильтру.
- Контракт строки поиска дополнен идентификатором проекта и безопасным отображаемым именем
  исполнителя. При отсутствии имени или проекта UI показывает нейтральное резервное значение.
- Нижняя панель показывает точное число выбранных задач и лимит операции. Переход к настройке
  изменений остаётся заблокирован до реализации задачи 017.

## Серверно проверяемый выбор всего результата

- `POST /api/tasks/select-all` принимает только фильтр и сортировку. Клиентские ID, количество,
  пагинация и признаки доступа отклоняются строгой схемой.
- Маршрут повторно проверяет сессию, право `app_access`, актуальный каталог полей и семантику
  фильтра перед обращением к Bitrix24-адаптеру.
- Ответ имеет три взаимоисключающих результата: пустой набор, точный набор из 1–1 000 уникальных
  ID или количество свыше лимита без передачи частичного списка. UI не строит выбор всего
  результата последовательным объединением страниц.
- Mock-адаптер вычисляет количество и ID из одного текущего снимка состояния. Производственный
  адаптер обязан сохранить эту атомарную семантику либо использовать эквивалентный механизм
  согласованного снимка.
- После успешного выбора UI обновляет текущую страницу. Изменение серверного количества между
  выбором и обновлением либо появление на странице ID вне подтверждённого набора снимает признак
  выбора всего результата и требует повторной проверки.
- Каждый запрос выбора всего результата связан с поколением состояния фильтра. Изменение фильтра
  или ручная очистка инвалидирует поколение, отменяет HTTP-запрос и сбрасывает observer мутации,
  поэтому запоздавший ответ старого запроса не может восстановить ID, счётчик, ошибку или признак
  полного выбора.
- Каждый последующий успешный ответ поиска сверяется с подтверждённым количеством и набором ID.
  Пагинация, reconnect или фоновое обновление, обнаружившие расхождение, переводят выбор в ручной
  режим и требуют повторного выбора всего результата.
- Во время смены страницы React Query сохраняет предыдущие строки как недоступный для выбора
  placeholder. Оболочка таблицы и пагинация не размонтируются; кнопки используют `aria-disabled`
  и сохраняют клавиатурный фокус до завершения запроса.
- Коррекция номера исчезнувшей страницы выполняется только по фактическому, не placeholder-ответу
  и сравнивает его границу с номером применённого запроса. Сервер принимает только точное число
  строк `min(pageSize, total - pageStart)` и отклоняет переполненные или неполные страницы.
- Если подтверждение изменения удаляет контрол, открывший модальный диалог, общий компонент
  возвращает фокус на заголовок конструктора фильтра вместо отсоединённого DOM-узла.
- Цвета выбора, статусов, приоритета и просроченности строятся только из семантических токенов
  `primary`, `muted`, `warning` и `destructive`, включая контрастные foreground-варианты и
  `color-mix`-подложки. Текстовые пары для компактных меток рассчитаны на порог WCAG AA 4,5:1.

## Граница последующих задач

- Текущий список выбранных ID является временным состоянием интерфейса, а не доказательством
  доступа или изменяемости задачи. Задача 019 повторно получает актуальные данные и проверяет
  доступ, статус, права и конфликт версии перед предварительным просмотром.
- Сохранение черновика операции, настройка изменений и активное действие перехода относятся к
  задаче 017. Миграции и изменения конфигурации для задачи 016 не требуются.
